> Читаемая, пригодная для дальнейшей разработки реконструкция **Translator3000** (стоковая версия `1.45.11`) для игр на Ren'Py — восстановлена из поставляемого `Translator3000.rpa`, полностью деобфусцирована и собирается обратно в один файл `Translator3000.rpa`, готовый к установке в игру.

Translator3000 автоматически переводит игры на Ren'Py прямо во время игры: перехватывает диалоги и меню, отправляет их в службу перевода, кэширует каждый результат в базе данных конкретной игры и показывает перевод вместо оригинального текста. Этот репозиторий существует потому, что актуальные исходники Translator3000 (v3) не публикуются, а старые публичные исходники v2 устарели на годы. Здесь последняя стоковая сборка восстановлена в чистые исходники, чтобы сообщество могло изучать её, исправлять и развивать.

## ✨ Возможности

### Перевод

- **Перевод в реальном времени** диалогов и меню выбора во время игры.
- **Четыре режима работы**: выключено, предварительное сканирование (перевод всей игры заранее), только БД (показ только переводов из базы данных) и реальное время + БД.
- **Много встроенных служб**: Google (GTX / client5 / RPC), Bing, DeepL (официальный API, RPC, Selenium), Yandex, Reverso и LingvaNex.
- **База переводов для каждой игры**: каждая переведённая строка кэшируется, повторное прохождение сцен не тратит новые запросы; готовая облачная база используется при наличии.
- Разбиение на предложения, контроль частоты запросов, поддержка прокси и Tor, подстановка переменных из базы данных.

### Панель в игре

- Панель настроек, открываемая прямо в игре: служба перевода, направление языков и режим работы.
- Настройки шрифта и отображаемого текста (размер, цвет, обводки, слои), автоматический выбор шрифта по целевому языку.
- Редактор переменных игры, редактор текста, настраиваемые сочетания клавиш, цветовые темы, перетаскиваемое окно переводчика с изменяемым размером.
- Лента уведомлений, статистика, управление кэшем переводов и резервная копия базы данных.

### Языки интерфейса

- Интерфейс на **английском (по умолчанию)**, русском, вьетнамском, чувашском и турецком языках.
- Вьетнамский язык — новое дополнение этой реконструкции, с полным покрытием строк.

### Совместимость

- Поддержка игр на **Ren'Py 7 (Python 2)** и **Ren'Py 8 (Python 3)** из одного архива — деревья модулей `py2` / `py3` упаковываются при сборке.
- Поставляется **одним файлом `.rpa`**: скопируйте его в папку `game` игры — и всё работает, другие файлы не нужны.

## 🚀 Установка

1. Соберите пакет (см. [Сборка](#-сборка)) или возьмите готовый `build/Translator3000.rpa`.
2. Скопируйте `Translator3000.rpa` в папку `game` вашей игры на Ren'Py.
3. Запустите игру и откройте панель Translator3000 его горячей клавишей, чтобы настроить службу перевода и режим работы.

> Не копируйте в игру отдельные файлы `.py` / `.rpy` — они переопределяют файлы внутри RPA. Ren'Py автоматически загружает каждый `.rpa` в папке `game`.

## 📖 Использование

1. Откройте панель Translator3000 в игре.
2. Выберите **службу перевода** и задайте **исходный / целевой языки**.
3. Выберите режим работы:
   - **Предварительное сканирование** — перевести всю игру в базу данных заранее (лучший опыт в дальнейшем).
   - **Только БД** — показывать переводы, уже имеющиеся в базе данных.
   - **Реальное время + БД** — сначала база данных, отсутствующие строки переводятся на лету.
   - **Выключено** — оригинальный текст.
4. Чтобы сменить язык интерфейса, используйте кнопку языка в панели (`EN` / `VI` / `RU` / …). При первом запуске по умолчанию английский.

## 🔧 Сборка

Требования:

- Python 3 (запускает `build.py` и упаковывает дерево модулей `py3`).
- Интерпретатор Python 2.7 (упаковывает дерево модулей `py2` в `.tr3000py`).
- Исполняемый файл игры или SDK Ren'Py 7 (компилирует `.rpy` в `.rpyc`).

```text
python build.py --renpy7-exe "C:\path\to\RenPy7Game.exe" --python2 "C:\path\to\python27\python.exe"
```

Результат: `build/Translator3000.rpa` (RPA-3.0).

Как это работает: файлы `.rpy` компилируются Ren'Py 7 во временной папке, модули `.py` кодируются в стоковый формат `.tr3000py` (AST → pickle → base64 → zlib — формат, который ожидает оригинальный `PyLoader`), и всё упаковывается в один RPA с точно такой же структурой времени выполнения, как у стоковой версии.

### Структура репозитория

```text
src/
  000translator3000_main.rpy        главный скрипт (GUI + ядро, деобфусцирован)
  translations/                     строки интерфейса (EN / VI / RU / CV / TR)
  _translator3000_main_modules/
    py2/_translator3000/*.py        модули для игр Ren'Py 7
    py3/_translator3000/*.py        модули для игр Ren'Py 8
  _translator3000_extra_modules/    сторонние библиотеки
  old_requests_module/  old_pkgutil_module/  uuid_py3_fix/  _extra_six.py
  Translator3000OtherFiles/         шрифты, изображения GUI, шаблоны
tools/                              инструменты деобфускации и генераторы переводов
build.py                            сборщик пакета
```

### Как восстанавливались исходники

Стоковый архив был распакован, его `.rpyc` декомпилирован с помощью unrpyc (пропатченного для чтения Python-кода, сохранённого автором в виде AST), а модули `.tr3000py` декодированы из сжатых AST-pickle обратно в Python-исходники. Затем безопасный проход статической свёртки превратил разрезанные / арифметически обфусцированные строки автора обратно в обычные литералы (например, `__version__ = '1.45.11'`). Комментарии и исходное форматирование по своей природе невосстановимы; динамическая обфускация и искажённые Ren'Py идентификаторы сохранены как есть для сохранения поведения.
